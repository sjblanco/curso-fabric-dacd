Cómo usar este material

Lo que debe dominar al terminar

  1. Describir los conceptos de data warehouse y los fundamentos del modelado dimensional.
  2. Crear tablas, cargar datos y conocer los métodos de ingesta de un warehouse de Fabric.
  3. Consultar y transformar datos con T-SQL y con el editor visual de consultas.
  4. Modelar los datos del warehouse para reportes.
  5. Proteger y monitorear un data warehouse.

Objetivos oficiales del módulo en Microsoft Learn (unos 70 minutos, con ejercicio práctico).

Ruta sugerida (unas 4 horas en total)

  1. Lea el módulo oficial en Learn (70 min), incluido su ejercicio.
  2. Recorra las 8 lecciones guiadas (60 min) y responda la pregunta de cada una.
  3. Haga los 4 simuladores (30 min).
  4. Responda la autoevaluación (15 min). Meta: 8 de 10.
  5. Haga el laboratorio (90 min) en su workspace de prueba.

Conviene haber terminado el F1-02: en el laboratorio se consulta el lakehouse que creó ahí.

Cada lección explica un concepto en lenguaje sencillo y lo conecta con el trabajo de la DACD. Lea en orden.

Simuladores

Practique cada concepto con las manos. Haga los cuatro simuladores en orden; cada uno trae instrucciones y la conclusión a la que debe llegar.

Cómo usar este simulador

  1. Para cada columna, elija dónde va: Hechos, dim_cliente, dim_producto o dim_fecha.
  2. Si se equivoca, lea la explicación e intente de nuevo.

Conclusión: la tabla de hechos guarda lo que se mide (montos, cantidades) y las claves de las dimensiones; las dimensiones guardan el contexto para filtrar y agrupar (quién, qué, cuándo).

Simulador 2. ¿Cómo cargo estos datos al warehouse?

Cuatro situaciones. Elija el método de carga que mejor encaja.

Pistas para elegir

  1. COPY INTO: carga masiva con una instrucción T-SQL desde archivos en almacenamiento.
  2. Pipeline: movimiento programado y orquestado desde otras fuentes.
  3. Dataflow Gen2: transformar con pasos visuales, sin código.
  4. CTAS o INSERT…SELECT: crear o llenar una tabla a partir de otra que ya está en Fabric, incluso en otro elemento del workspace.

Simulador 3. ¿Warehouse o SQL analytics endpoint?

Los dos usan el mismo motor SQL, pero no hacen lo mismo. Decida en cada caso.

Pistas para elegir

  1. Warehouse: DDL y DML completos (crear, insertar, actualizar, borrar) y transacciones ACID de varias tablas.
  2. SQL analytics endpoint: se crea con cada lakehouse; consulta sus tablas Delta y permite crear vistas, funciones y procedimientos, pero no modifica los datos.

Simulador 4. ¿Qué control de seguridad aplico?

Proteger datos de clientes no es opcional. Elija el control adecuado para cada necesidad.

Pistas para elegir

  1. Rol del workspace: acceso general a todo el contenido del workspace.
  2. Seguridad a nivel de fila: cada persona ve solo ciertas filas.
  3. Seguridad a nivel de columna: ciertas columnas no se pueden ver en absoluto.
  4. Enmascaramiento dinámico: la columna se ve, pero con el valor parcialmente oculto.
